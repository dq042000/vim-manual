畫面地圖：先搞懂你在哪一格

<leader> 就是空格鍵。忘記時按空格停一下，下方會跳出所有可按的鍵（which-key）。

最上方橫條 = 已開的檔案（buffer，不是標籤頁！） Shift+h 上一個檔案　Shift+l 下一個檔案　<leader>bd 關掉這個檔案
左：檔案樹（neo-tree）
打開／關掉：<leader>e
跳去中間：Ctrl+l
看說明：?
中：編輯區
跳去左邊檔案樹：Ctrl+h 或 sh
跳去右邊：Ctrl+l 或 sl
這格滿版 ⇄ 還原：Ctrl+b
右：Claude 側欄
開／關：Alt+r
跳回中間：Ctrl+h
變回 normal mode：連按兩下 Esc

我想要⋯

在左／中／右之間跳來跳去

Ctrl+h Ctrl+l往左／往右一格（在哪一格都能用，最推薦）
Ctrl+j Ctrl+k往下／往上一格
sh sl sj sk同上（你自訂的），但檔案樹裡不能用
Ctrl+w 再按 w依序輪流跳到下一格
Ctrl+w 再按 p跳回上一格待過的地方
為什麼在檔案樹按 sl 沒用？ 因為 s 在檔案樹裡是「用垂直分割打開檔案」，按下去就立刻執行了。 所以從檔案樹回中間，請用 Ctrl+l。

左邊檔案樹裡面的操作

<leader>e打開檔案樹；已開著時再按會關掉（要跳進去用 Ctrl+h）。
例外：目前顯示的是 git 改動清單時，這個鍵會切回一般檔案列表
<leader>E用目前工作目錄開檔案樹
Enter 或 l開檔案／展開資料夾
h收起資料夾
z全部資料夾收起來
s ／ S ／ t用垂直分割／水平分割／新標籤頁開
P預覽檔案（不真的打開）
a ／ A新增檔案／新增資料夾（檔名結尾打 / 也會變資料夾）
r ／ d改名／刪除
y x p複製／剪下／貼上檔案
c ／ m複製到／移動到（打路徑）
Y複製這個檔案的完整路徑
O用系統程式開啟
H顯示／隱藏被收起來的資料夾（node_modules、vendor 等）
/在檔案樹裡搜尋檔名
Backspace ／ .往上一層／把這個資料夾設為根目錄
R重新整理
?顯示檔案樹所有按鍵
q關掉檔案樹

上方檔名列：切換／關閉已開的檔案

Shift+h ／ Shift+l上一個／下一個檔案
[b ／ ]b同上
<leader>,列出已開的檔案，打字挑一個
<leader>bj每個檔名旁出現字母，按字母直接跳
<leader>bb 或 <leader>`切回上一個看過的檔案
<leader>bd關掉目前檔案（視窗保留）
<leader>bo只留目前這個，其他全關
<leader>bl ／ <leader>br關掉左邊／右邊全部
<leader>bp釘選這個檔案（<leader>bP 關掉沒釘選的）
[B ／ ]B把檔名往左／右挪
最常搞混：上方那排是「已開的檔案」，不是標籤頁。 所以按 Tab 不會換檔案，換檔案請用 Shift+h ／ Shift+l。
檔名旁的圖示：黃點 ● 或 [+] = 改過還沒存檔； 紅色圖示 = 這個檔案有錯誤，看內容請見「程式碼」卡片。

標籤頁（整組版面）

Tab ／ Shift+Tab下一個／上一個標籤頁（自訂）
te開新標籤頁，打檔名再按 Enter（自訂）
<leader>Tab Tab開新標籤頁
<leader>Tab ] ／ [下一個／上一個標籤頁
<leader>Tab d關掉這個標籤頁
<leader>Tab o關掉其他標籤頁
gt ／ gTvim 原生的下一個／上一個標籤頁
標籤頁是什麼：一整組視窗排版，不是一個檔案。 例如一個標籤頁放前端、另一個放後端，切過去整個版面一起換。 只有一個標籤頁時，畫面上看不到標籤列。

分割視窗、滿版、調大小

sv 或 <leader>|左右分割（自訂／內建）
ss 或 <leader>-上下分割（自訂／內建）
Ctrl+b目前這格滿版 ⇄ 還原（自訂）
<leader>wd關掉目前這格視窗
Ctrl+← Ctrl+→視窗變窄／變寬
Ctrl+↑ Ctrl+↓視窗變高／變矮
Ctrl+w 再按 =所有視窗平均分配大小
<leader>uz禪模式（只留中間，專心寫）
注意：Ctrl+b 已改成滿版，往上翻頁請用 Ctrl+u。

找檔案、搜內容

<leader>Space用檔名找檔案（像 VSCode 的 Ctrl+P）
<leader>/全專案搜內容（像 VSCode 的 Ctrl+Shift+F）
<leader>fr最近開過的檔案
<leader>sw搜游標所在的字
<leader>sb只在目前檔案搜
<leader>ss跳到這個檔案的函式／類別
<leader>sr全專案搜尋並取代
<leader>sR重開上一次的搜尋結果
<leader>fn開新檔案
搜尋視窗裡（fzf-lua）：Ctrl+j／Ctrl+k 上下選， Enter 開啟，Ctrl+v 分割開、Ctrl+t 丟進 Trouble 清單， F4 開關預覽，Alt+i 顯示被 .gitignore 忽略的檔案，Esc 按一次就關掉。
右邊預覽區只能捲，游標跳不進去。Shift+↓／Shift+↑ 捲一頁， Alt+Shift+↓／Alt+Shift+↑ 捲一行，F3 開關自動換行。 因為那塊是 fzf 這個程式自己畫的文字，不是獨立的 Neovim 視窗。

程式碼：跳定義、看錯誤

gd跳到定義
gr列出誰用到它
gI ／ gy跳到實作／型別定義
Ctrl+o ／ Ctrl+i跳回剛剛的位置／再跳回來
K看說明文件（hover）
<leader>cr重新命名（全專案一起改）
<leader>cacode action（自動修正建議）
<leader>cf格式化
]d ／ [d下一個／上一個問題（錯誤或警告）
]e ／ [e只跳錯誤
<leader>cd顯示這行的錯誤訊息
<leader>xX目前檔案的錯誤清單（Trouble，再按一次關）
<leader>xx所有開著的檔案的錯誤清單（Trouble）
<leader>sd用搜尋視窗列出錯誤，可打字篩選
常用做法：先 ]e 跳到錯誤，再 <leader>cd 看訊息。

編輯、存檔、離開

Ctrl+s存檔
Ctrl+a全選（自訂；原本的「數字 +1」被蓋掉了）
gcc ／ 選取後 gc註解／取消註解
Alt+j ／ Alt+k整行往下／往上搬
s 再打兩個字Flash：畫面上任何地方直接跳過去
u ／ Ctrl+r復原／重做
Esc離開輸入模式，順便清掉搜尋的黃色標記
Ctrl+/開／關下方終端機
<leader>qq離開 nvim

Markdown：預覽 .md 檔

（不用按鍵）打開 .md 檔就自動美化標題、清單、程式碼區塊
<leader>cp在瀏覽器開／關即時預覽，邊打字邊同步（再按一次關）
:MarkdownPreview ／ :MarkdownPreviewStop同上，指令版
自動美化是 render-markdown.nvim 做的，游標移到哪一行，那一行就變回原始語法方便你編輯，移開又變回美化樣子。
<leader>cp 只在 .md 檔有效，所以下面「全部快速鍵」那張表查不到它。 第一次按沒反應時，在 nvim 裡執行 :Lazy build markdown-preview.nvim 補裝。

Git：所有 git 按鍵都在這裡

<leader>gglazygit（最常用；專案根目錄）
<leader>gGlazygit（目前工作目錄）
<leader>ge用左邊檔案樹列出有改動的檔案（再按一次關掉）
<leader>gs改動檔案清單，右邊看 diff
<leader>gd改動檔案清單，另一種排版
<leader>gS列出 stash
<leader>gl整個 repo 的 commit 歷史
<leader>gL同上，但預覽區可以把游標移進去（按 Alt+w 切換焦點）
<leader>gf只看目前這個檔案的 commit 歷史
<leader>gb這行是誰改的（blame）
<leader>gB ／ <leader>gY用瀏覽器開這行的 GitLab／GitHub 頁面／只複製網址
commit 清單裡的 Enter 是 checkout 那個 commit，不是開起來看，小心。 只想複製 hash 按 Ctrl+y，想看改了哪些檔案按 Ctrl+d。
<leader>gs 的清單裡，→ 是 stage、← 是 unstage、Ctrl+x 是丟棄改動。
<leader>ge 之後怎麼回到原狀： 想關掉檔案樹就再按一次 <leader>ge（或在樹裡按 q）； 想變回一般的檔案列表按 <leader>e； 只想把游標移回程式碼、檔案樹留著就按 sl。 這時的 <leader>e 是切換而不是關閉，它會把 git 清單換成一般檔案樹。 在檔案樹裡按 < 和 > 可以循環三種清單：一般檔案 → 開著的 buffer → git 改動。

改動區塊（左邊那條彩色直線）

]h ／ [h跳到下一個／上一個改動
]H ／ [H跳到最後一個／第一個改動
<leader>ghp就地展開這塊改動的 diff
<leader>ghs ／ <leader>ghrstage／還原這塊改動（先選取可以只處理幾行）
<leader>ghS ／ <leader>ghRstage／還原整個檔案
<leader>ghu取消上一次的 stage
<leader>ghb ／ <leader>ghB這一行的完整 blame／整個檔案的 blame
<leader>ghd ／ <leader>ghD開分割視窗和 index／上一個 commit 比對
dih把一塊改動整個刪掉（ih 是「一塊改動」這個範圍）
這組鍵只在 git repo 裡的檔案有效，所以下面「全部快速鍵」那張表查不到它們。 游標所在行尾自動顯示的作者、日期、commit 訊息也是這個套件（gitsigns）做的。

看到 <M-j> 這種寫法時的對照表

下面的表格已經直接寫成 Alt+j 了。 但你在 nvim 裡按 <leader>sk、或翻 ~/.config/nvim 設定檔時，看到的還是這種原始寫法。

<M-j>Alt + j。M 是 Meta 鍵，在 Linux／Windows 就是 Alt
<C-j>Ctrl + j。大小寫不影響，<C-J> 一樣是按 Ctrl+j（不用加 Shift）
<S-Tab>Shift + Tab。S 是 Shift
<leader>空格鍵。按了停一下，下方會列出接著能按的鍵
Space出現在中間時（例如 <leader> Space）是真的再按一次空格鍵
<CR>Enter（carriage return）
<BS>Backspace 退格鍵
<Esc> <Tab>就是鍵盤上的 Esc、Tab
<Up> <Down> <Left> <Right>方向鍵上、下、左、右那四顆（表格裡寫成 ↑ ↓ ← →）
<C-/>Ctrl + 斜線（/ 那顆）
<lt>< 這個符號本身，不是修飾鍵
<C-W><C-D>連按兩組：先 Ctrl+w 放開，再 Ctrl+d（表格裡寫成 Ctrl+w Ctrl+d，中間有空格就是分開按）
<Plug>(…)出現在說明欄時，代表那是外掛內部的名字，不是你要按的鍵
Alt 按下去沒反應？改成先按一下 Esc、放開，再按那個字母。 終端機把「Esc 之後接一個鍵」當成跟 Alt 同樣的意思。 Mac 要先到終端機設定把 Option 當成 Meta，否則 Alt+j 會打出奇怪符號。
兩個字母連著寫（例如 sl、te、gcc）是依序快速按，不是一起按。
